# Finance Lab — 개인화 리서치 설계

> [!important] 제품 경계
> 개인화 대상은 투자 종목이 아니라 **리서치 시스템**이다. LLM은 스킬, 플러그인, MCP, 훅, 감시 소스, 실행 주기, 검증 수준과 토큰 예산을 제안한다. 매수·매도·보유·비중·적합성 판단과 거래 실행은 제공하지 않는다.

## 한 줄 정의

사용자의 목표와 몇 가지 설문 답변을 검사 가능한 `Research Mandate`로 바꾸고, 로컬 Agent Observatory에 설치된 기능 중 가장 안전하고 비용 효율적인 리서치 조합을 제안하는 Finance 전용 작업 공간.

## 사용 흐름

1. 목표, 관찰 기간, 관심 도메인, 보고서 깊이, 알림 선호, 예산, 개인정보 보관 방식을 답한다.
2. LLM이 종목이 아닌 기능 구성을 추천한다.
3. 사용자는 추천 이유, 권한, 소스, 비용, 실행 주기, 한계를 미리 본다.
4. 설치·자격 증명·소스 감시·예약 실행을 각각 승인한다.
5. 수집 결과는 단서/사실/파생 분석/충돌 상태로 나뉘고 출처와 관찰 시각을 보존한다.
6. 예산 초과, 출처 장애, 검증 실패는 숨기지 않고 중단 또는 성능 저하 상태로 표시한다.

## Serenity 감시 아이디어

- 데모 대상: X의 `Serenity (@aleabitoreddit)`.
- 운영 연결 전 계정 식별을 다시 검증한다.
- 공개 포스트는 `unverified_lead`로만 수집한다.
- 공식 X API 또는 명시적으로 허용된 제공자만 사용한다.
- 포스트 ID, 작성자 ID, URL, 작성/수집 시각, 수정/삭제 상태를 기록한다.
- 기업 공시·기업 발표·규제기관 자료 등 1차 출처와 교차검증한 뒤에만 사실 요약에 포함한다.
- 브라우저 쿠키 탈취, 접근 제한 우회, 약관에 반하는 크롤링은 사용하지 않는다.

## 토큰 최적화

- 새 ID/수정 여부를 메타데이터로 먼저 확인한다.
- 중복 제거와 저비용 관련성 분류 후에만 원문을 가져온다.
- 변하지 않은 소스는 재요약하지 않는다.
- 라우팅·분류는 저비용 모델, 최종 근거 종합만 상위 모델을 사용한다.
- 알림을 묶고 quiet hours를 적용한다.
- 실행·월 단위 하드 한도를 두며 80%부터 깊이를 자동 축소하고 100%에서 비필수 작업을 중단한다.

## 구현 원칙

- 제안과 실행을 분리한다.
- 기본은 읽기 전용이다.
- 비밀값은 프롬프트와 그래프에 기록하지 않는다.
- 소셜 콘텐츠는 신뢰하지 않는 입력으로 격리한다.
- 프로필 답변은 종목 순위에 영향을 주지 않는다.
- 모든 자동화는 마지막 실행, 다음 실행, 예상/실제 비용, 중단 이유를 보여준다.
