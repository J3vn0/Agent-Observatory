## Measurement boundary

The dashboard does not claim actual work efficiency yet. The current reuse proxy is derived from observed uses, graph connections, and project breadth. Success rate, outcome quality, elapsed time, and token cost must be collected before an efficiency metric is valid.

Recent timestamps remain evidence only because some scanner observations can use file modification time as a fallback.

## Why descriptions repeat

The scanner intentionally avoids exposing prompts, messages, and private session metadata. It assigns privacy-safe descriptions from normalized roles. Multiple executions with the same role can therefore share one description even when their parent session or project differs. The UI now exposes that provenance instead of presenting the text as a unique execution summary.

## Deployment decision

- Keep the local ADE native: loopback dashboard plus local Node.js daemon.
- Do not require Docker for host scanning, worktree discovery, MCP stdio inspection, or local filesystem watching.
- Consider containers later for hosted team services, isolated MCP probes, scheduled finance collectors, or reproducible CI.
- Prefer a native desktop launcher as the next packaging step.

See `docs/architecture/DEPLOYMENT_STRATEGY.md`.
